Olist SQL Analysis

Project Overview

This project explores the Olist Brazilian e-commerce dataset using SQL to analyze sales performance, order trends, payment behavior, product categories, and geographic revenue distribution.

The goal is to extract meaningful business insights using SQL queries and demonstrate practical data analysis skills.

Tools & Technologies

* MySQL
* MySQL Workbench
* SQL

Dataset

The project uses the publicly available Olist Brazilian E-Commerce dataset, which contains information about orders, customers, products, payments, and order items.

Key Business Questions

* How many orders are recorded in the dataset?
* How are orders distributed by status?
* How do order volumes change over time?
* What are the total sales and freight costs?
* Which payment methods are most frequently used?
* Which product categories generate the highest revenue?
* Which customer states contribute the most revenue?
* What is the average order value?

SQL Skills Demonstrated

* Data aggregation using COUNT(), SUM(), and AVG()
* Filtering and sorting using WHERE and ORDER BY
* Grouping data using GROUP BY
* Joining multiple tables using JOIN
* Date-based analysis using DATE_FORMAT()
* Subqueries for calculating business metrics
* Revenue and payment analysis

Key Findings

1. Sales Performance

* Total Sales: BRL 13,591,643.70
* Total Freight: BRL 2,251,909.54
* Average Order Value: BRL 137.75

2. Payment Analysis

* Credit cards were the most frequently used payment method.
* Credit cards also accounted for the largest share of total payment value.
* Boleto was the second most frequently used payment method.

3. Product Category Performance

The highest-revenue product categories were:

1. Health & Beauty — BRL 1,258,681.34
2. Watches & Gifts — BRL 1,205,005.68
3. Bed, Bath & Table — BRL 1,036,988.68
4. Sports & Leisure — BRL 988,048.97
5. Computers & Accessories — BRL 911,954.32

4. Geographic Revenue Analysis

São Paulo generated the highest revenue, followed by Rio de Janeiro and Minas Gerais.

This indicates that these states were major contributors to the business’s sales performance.

Project Limitations

The imported orders table currently contains fewer records than the original dataset. Therefore, order-related metrics and any findings that depend on the completeness of the orders table should be interpreted with caution.

Conclusion

This project demonstrates how SQL can be used to explore e-commerce data, calculate business metrics, compare sales performance, and identify important trends across products, payments, and geographic regions.

It also demonstrates practical skills in data aggregation, table joins, date-based analysis, and business intelligence.
